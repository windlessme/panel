# 繁體中文版（v4）

這個分支（`i18n-v4`）以官方正式版 **v4.6.2** 為基礎，加上台灣繁體中文介面。除了翻譯之外，功能、資料庫結構和安裝方式都跟官方 v4.6.2 一樣，沒有新增 migration。

## 使用方式

- 第一次開啟面板時，瀏覽器語言是中文（`zh*`）就顯示繁體中文，其他語言顯示英文。
- 右上角頭像選單（手機版在選單最下方）可以切換「English／繁體中文」，選擇會記在瀏覽器裡。
- 表單驗證、登入錯誤等後端訊息也會跟著介面語言切換。

## 安裝與更新

發布檔放在 fork 的 Releases：<https://github.com/windlessme/panel/releases>。每個版本的 `panel.tar.gz` 都已經建好前端，用法和官方發布檔一樣。下面的指令都在面板主機上以 root 執行。

### 全新安裝

照官方的 [Getting Started](https://convoypanel.com/docs/panel/v4/getting-started) 操作，只有下載那一步換成這個 fork：

```bash
mkdir -p /var/www/convoy && cd /var/www/convoy
curl -Lo panel.tar.gz https://github.com/windlessme/panel/releases/latest/download/panel.tar.gz
tar -xzvf panel.tar.gz
```

其餘步驟（`.env`、`docker compose up -d`、`composer install`、`key:generate`、`migrate`、建立使用者）完全照官方文件。

### 把現有的官方 v4 面板換成中文版

照官方的 [Updating the Panel](https://convoypanel.com/docs/panel/v4/updating-the-panel) 操作，只有下載那一步換成這個 fork：

```bash
cd /var/www/convoy
docker compose down
cp -a /var/www/convoy /var/www/convoy.bak-$(date +%Y%m%d)   # 先備份

curl -L https://github.com/windlessme/panel/releases/latest/download/panel.tar.gz | tar -xzv

docker compose up -d --build
docker compose exec workspace composer install --no-dev --optimize-autoloader
docker compose exec workspace php artisan migrate --force
docker compose exec workspace php artisan optimize
docker compose restart
```

`.env` 不在發布檔裡，解壓縮不會覆蓋它。

> **面板還在 v4.6.1 以前的版本時要注意**：v4.6.2 會把 MySQL 從 8.0 升到 8.4，第一次啟動時會直接升級資料目錄，**無法退回**。這是官方 v4.6.2 本身的變更，跟翻譯無關，但升級前務必先備份。

升級前如果想讓使用者看到維護頁、等佇列跑完，可以照官方文件先執行 `php artisan down --secret=...`，並到 `/horizon` 確認沒有進行中的工作。

### 一次更新多台面板

在自己的電腦上，把面板主機列在 `HOSTS` 裡（需要能用 SSH 以 root 登入）：

```bash
HOSTS="panel1.example.com panel2.example.com"
for host in $HOSTS; do
  echo "==> $host"
  ssh root@"$host" 'set -e
    cd /var/www/convoy
    docker compose down
    cp -a /var/www/convoy /var/www/convoy.bak-$(date +%Y%m%d%H%M)
    curl -fsSL https://github.com/windlessme/panel/releases/latest/download/panel.tar.gz | tar -xz
    docker compose up -d --build
    docker compose exec -T workspace composer install --no-dev --optimize-autoloader
    docker compose exec -T workspace php artisan migrate --force
    docker compose exec -T workspace php artisan optimize
    docker compose restart' || echo "!! $host 更新失敗"
done
```

建議先在一台面板上跑過，確認沒問題再更新其他台。

### 退回官方版

這個分支沒有改資料庫，退回時只要照「更新」的步驟，把下載網址換回官方的 `https://github.com/convoypanel/panel/releases/latest/download/panel.tar.gz`。

## 跟上游同步

官方發布新版（例如 v4.6.3）時：

```bash
# 第一次：git remote add upstream https://github.com/ConvoyPanel/panel.git
git fetch upstream --tags
git checkout i18n-v4
git merge v4.6.3            # 或 git rebase v4.6.3
npm run i18n:todo           # 列出新版新增、還沒翻譯的字串
# 把新字串翻進 lang/zh_TW/ 對應的檔案
npm run i18n:check          # 要顯示 i18n: OK
```

接著在 `CHANGELOG.md` 最上面加一段 `## v4.6.3-zhtw.1`，commit 後推送 tag：

```bash
git tag v4.6.3-zhtw.1 && git push fork i18n-v4 v4.6.3-zhtw.1
```

GitHub Actions 的 Release workflow 會檢查翻譯、建好前端，並建立草稿 release。到 Releases 頁面按「Publish release」後，`releases/latest` 就會指向新版。

## 翻譯檔結構

- `lang/en_US/` 是英文原文，`lang/zh_TW/` 是繁體中文，兩邊的檔案和 key 一一對應。目錄結構沿用官方原本給 Crowdin 用的格式，以後官方開放翻譯時也能直接對應。
- 前端透過 `/locales/locale.json` 讀取這些檔案。命名空間就是檔案路徑，例如 `lang/zh_TW/admin/nodes/index.php` 對應 `useTranslation('admin.nodes.index')`。
- 字串裡的 `:name` 是變數，翻譯時要原樣保留；`zod.php` 用的是 `{{name}}`，`<0></0>` 是包住連結或粗體的標籤，也要保留。
- `npm run i18n:check` 會檢查：
  - 前端用到的 key 在英文檔裡都存在
  - 繁體中文沒有缺漏，變數和標籤跟英文一致
  - 沒有中國用語（服務器、網絡、默認、內存……）
  - 中文旁邊沒有半形標點、中文字之間沒有多餘空格、沒有用 `...` 代替 `…`
