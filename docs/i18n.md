# 多語系（i18n）與繁體中文分支說明

這個分支（`i18n`）在 Convoy 上加了多語系支援，目前提供 English 與台灣繁體中文。

## 使用方式

- 面板右上角頭像選單 → **Language / 語言**，選了會重新整理頁面並記住選擇（存在瀏覽器 `localStorage`）。
- 沒選過的話，瀏覽器語言是 `zh*` 就顯示繁體中文，其他顯示英文。
- 前端每個 API 請求都帶 `Accept-Language`，後端的驗證錯誤與錯誤訊息會跟著切換。

## 運作方式

| 部分 | 位置 |
| --- | --- |
| 前端初始化、語言偵測、切換 | `resources/scripts/lib/i18n.ts` |
| 前端翻譯檔 | `resources/scripts/locales/zh-TW.json`（`en.json` 只放英文單複數） |
| 後端語系 middleware | `app/Http/Middleware/SetLocale.php` |
| 後端翻譯檔 | `lang/zh_TW/*.php`、`lang/zh_TW.json` |
| 檢查工具 | `scripts/i18n.mjs` |

**翻譯 key 就是英文原文**，例如：

```tsx
import { t } from '@/lib/i18n.ts'

<Button>{t('Save changes')}</Button>
t('Delete {{name}}?', { name: server.name })
t('{{count}} servers', { count: servers.length }) // 英文單數寫在 locales/en.json 的 "{{count}} servers_one"
```

英文不需要翻譯檔（找不到翻譯就顯示 key 本身），所以漏翻的字串只會顯示英文，不會壞掉。

切換語言時會重新整理頁面，所以在模組最外層呼叫 `t()`（表格欄位定義、zod schema、常數表）是安全的。

同一個英文字在不同畫面意思不同時，用 i18next 的 context 拆開：`t('Type', { context: 'verb' })` 會查 `Type_verb`，
找不到再退回 `Type`。zod 沒有自訂訊息的欄位，中文介面會用 `lib/i18n.ts` 裡的錯誤對照（例如「此欄位為必填。」）。

## 指令

```bash
npm run i18n:sync    # 掃描所有 t() 呼叫，把新 key 加進 zh-TW.json（值為空），刪掉沒用到的 key
npm run i18n:todo    # 列出還沒翻譯的 key 與所在檔案
npm run i18n:lint    # 檢查翻譯：中國用語、半形標點、{{變數}} 是否一致
npm run i18n:check   # 以上全部，有問題就 exit 1（CI 會跑）
```

## 新增或修改畫面時

1. 新的文字一律包 `t('English text')`，變數用 `{{name}}`。
2. `npm run i18n:sync` → 在 `zh-TW.json` 補上翻譯。
3. `npm run i18n:check` 通過再 commit。

翻譯用詞請對照本文件最後的詞彙表，並遵守台灣用語：全形標點（，。：；！？「」），中英文之間留半形空格，不要用中國用語（服務器、網絡、默認、支持、設置、用戶、數據⋯⋯）。

## 跟上游同步

```bash
git remote add upstream https://github.com/ConvoyPanel/panel.git   # 只需一次
git fetch upstream
git checkout i18n
git merge upstream/main           # 有衝突就手動解，通常是被包了 t() 的那幾行
npm ci && npm run build && npm run tc
npm run i18n:sync                 # 上游新增的英文字串會出現在 zh-TW.json（空值）
npm run i18n:todo                 # 補翻譯
npm run i18n:check
git push fork i18n                # 推上去後 GitHub Actions 會自動建置 ghcr.io/windlessme/panel:i18n
```

上游新加、還沒包 `t()` 的文字會照樣顯示英文，可以之後再補。

## 部署到多台面板

推送到 `i18n` 分支後，GitHub Actions（`.github/workflows/docker.yml`）會建置 amd64 + arm64 映像檔並推到
`ghcr.io/windlessme/panel:i18n`，另外也會打上 `sha-<commit>` 標籤，方便固定版本。

> **第一次使用前**：fork 預設不跑 Actions。到 https://github.com/windlessme/panel/actions 按
> 「I understand my workflows, go ahead and enable them」，再到 Actions → Docker → **Run workflow**（選 `i18n` 分支）
> 手動跑第一次。之後每次推送都會自動建置。

> 第一次建置完，到 GitHub → 個人頁 → Packages → `panel` → Package settings，把 visibility 改成 **Public**，
> 其他主機才能不登入就 pull。保持 Private 的話，每台主機要先
> `echo <PAT> | docker login ghcr.io -u windlessme --password-stdin`（PAT 需要 `read:packages`）。

### 全新安裝

```bash
curl -fsSL https://raw.githubusercontent.com/windlessme/panel/i18n/docker/install.sh | sudo \
  CONVOY_REPO=https://raw.githubusercontent.com/windlessme/panel \
  CONVOY_IMAGE=ghcr.io/windlessme/panel \
  bash -s -- --version i18n --domain panel.example.com --email you@example.com
```

### 已經裝好的面板改用這個版本

在安裝目錄（預設 `/opt/convoy`）的 `.env` 加兩行：

```dotenv
CONVOY_IMAGE=ghcr.io/windlessme/panel
CONVOY_VERSION=i18n
```

然後：

```bash
cd /opt/convoy
convoyctl upgrade        # 備份 → pull 新映像檔 → 重啟 → 檢查
```

之後每次更新也一樣只要 `convoyctl upgrade`。要一次更新多台，可以用 SSH 迴圈：

```bash
for host in panel1 panel2 panel3; do
  ssh root@$host 'cd /opt/convoy && convoyctl upgrade'
done
```

想固定在某個版本，把 `CONVOY_VERSION` 改成 `sha-xxxxxxx`（GitHub Packages 頁面上看得到），或在 fork 上打
`v*.*.*` tag 讓 workflow 產生版本號。

### 要退回官方版

把 `.env` 的 `CONVOY_IMAGE` 那行刪掉、`CONVOY_VERSION` 改回原本的版本，再 `convoyctl upgrade`。
資料庫結構跟官方版相同（這個分支沒有新增 migration），可以直接切換。
